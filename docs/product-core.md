# HTML Edit 产品核心定义

> 状态：**已确认并冻结的产品基线 v1**
> 生效日期：2026-08-20
> 权威关系：本文定义“做什么、先做什么、暂不做什么”；具体实现以 [`engineering-plan.md`](engineering-plan.md) 为准。两份文档必须保持一致。

## 1. 产品定义

**HTML Edit 是一个人工操作优先、面向真实 HTML 项目的可视化多媒体编排器。**

它直接打开并运行标准 HTML、CSS 和 JavaScript 项目，让用户在真实浏览器画布中选择和修改 DOM 元素，并用剪辑软件式多轨时间线编排页面动画、视频、音频和交互。

长期产品关系为：

```text
真实 HTML 可视化画布
+ 非破坏性源码回写
+ 多轨时间线
+ 页面交互与状态编排
+ 可供人工与 Agent 共用的结构化编辑内核
```

第一版的实施优先级明确为：

```text
先让人完整、顺手、可靠地使用
→ 再完成时间线与交互闭环
→ 最后接入 Agent、插件和外部自动化
```

HTML Edit 不是把网页截图放入视频时间线，也不是用私有设计画布替代 HTML。编辑对象、浏览器预览对象、源码对象和最终运行对象必须保持一致。

## 2. 产品成立的五项核心能力

### 2.1 真实 HTML 可视化编辑

编辑器必须直接处理标准 HTML 项目，并在真实 Chromium 运行环境中完成可视化编辑。

必须支持：

- 打开、保存和继续维护标准 HTML、CSS、JavaScript 项目；
- 在画布中悬停、选择和定位真实 DOM 元素；
- 直接编辑文字、图片、视频、SVG、容器和受支持的自定义组件；
- 调整布局、尺寸、间距、层级、基础样式和响应式状态；
- 让画布、DOM 图层树、属性面板、时间线和源码保持同步选择；
- 保留项目原有结构与独立运行能力，不将页面扁平化为截图或不可回编格式。

核心原则：

```text
画布中的对象
= 浏览器中运行的对象
= 源码中可定位的对象
= 时间线和交互系统引用的对象
```

MVP 首先完整支持普通静态 HTML、CSS、JavaScript 项目。React、Vue、Next.js 等框架项目的源码级双向可视化编辑后置，不作为第一版成立条件。

### 2.2 非破坏性源码回写

“能在画布上改”不等于“产品成立”。用户修改必须安全回写到原项目，并尽量避免无关源码变化。

必须遵守：

- 不使用 `document.documentElement.outerHTML` 等方式整页重新序列化；
- 修改文字、属性和稳定 ID 时，只改动对应源码区间；
- 视觉样式默认进入 `html-edit.generated.css`，避免大面积重写用户原 CSS；
- 保留无关 HTML、JavaScript、注释、格式和文件结构；
- 保存采用原子写入，并保留可恢复历史；
- 保存失败时不得覆盖最后一份有效项目；
- 用户关闭并重新打开项目后，编辑结果仍然存在，页面仍可独立运行。

每个进入持久编辑、时间线或交互系统的元素使用稳定 ID：

```html
data-he-id="he_xxxxx"
```

不得长期依赖以下脆弱定位方式：

```text
:nth-child()
XPath
DOM index
临时图层顺序
仅靠 CSS class
```

### 2.3 剪辑软件式多轨时间线

时间线是产品主编辑界面之一，不是附加动画面板。

时间线统一管理：

- 场景与章节；
- DOM 元素及其可动画属性；
- 视频、音频和字幕；
- SVG、Canvas、WebGL 与自定义组件状态；
- 进入、停留、退出和场景转场；
- 与时间有关的事件和交互动作。

第一版基础体验必须包含：

- 播放、暂停和定位；
- Playhead 拖动与实时画面回看；
- 时间线缩放；
- 多轨道排列、分组基础和轨道状态；
- 片段移动、裁切、拆分和复制；
- 时间吸附；
- 轨道锁定、显示、隐藏和静音；
- 关键帧增加、删除、移动和复制；
- 基础缓动；
- DOM、视频和音频在同一时间基准下同步。

时间线数据必须结构化保存，不能只存在于不可解析的 JavaScript 或某个动画库的私有 API 中。

固定关系为：

```text
timeline.json
→ HTML Edit Timeline Compiler
→ Playback Plan
→ Web Animations API / HTMLMediaElement
```

未来可以增加 GSAP、Three.js、3DGS Camera、Lottie 等 Adapter，但项目数据不得等同于任何单一运行库。

### 2.4 页面交互与状态编排

产品编辑的是可交互页面，而不仅是固定时间播放的动画。

第一版触发器包括：

- 点击；
- 悬停；
- 页面或场景进入；
- 元素进入视口；
- 时间事件。

第一版动作包括：

- 播放、暂停或定位时间线；
- 显示或隐藏元素；
- 修改基础状态；
- 播放或暂停媒体；
- 跳转到锚点或场景。

固定时间动画和用户触发交互必须能够在同一页面共存，并有明确的状态、优先级和回退逻辑。交互同样使用结构化数据保存，不能散落为无法审查的内联脚本。

### 2.5 结构化编辑内核与 Agent 后置

第一版不把 Agent 作为产品成立条件，但从第一天就统一人工编辑入口。

人工操作必须经过：

```text
UI Intent
→ Command
→ Operation
→ Transaction
→ Project / Timeline / Interaction Service
→ Preview + Persistence
```

第一版只建设：

- 统一 `Command / Operation`；
- Zod Schema；
- 稳定 `targetId`；
- `revision` 与冲突检查；
- Transaction；
- Undo / Redo；
- 可记录、可比较的变更。

后续再在同一内核上增加：

- REST；
- WebSocket；
- Plugin SDK；
- MCP；
- 专业 Agent；
- 通用编码 Agent。

人工与 Agent 最终必须共用同一套命令语义，但 Agent 接入不得延误第一版人工可操作性。

## 3. 核心界面结构

产品采用专业设计工具与非线性剪辑软件共同形成的基本布局：

```text
┌─────────────────────────────────────────────────────────────┐
│ 项目 / 保存 / Undo / Redo / 预览 / 导出                    │
├──────────────┬──────────────────────────┬───────────────────┤
│ Layers       │                          │ Inspector         │
│ Scenes       │    REAL HTML CANVAS      │ Layout            │
│ Assets       │                          │ Style             │
│              │                          │ Animation         │
│              │                          │ Interaction       │
├──────────────┴──────────────────────────┴───────────────────┤
│                    TIMELINE                                 │
└─────────────────────────────────────────────────────────────┘
```

画布、图层树、属性面板和时间线之间必须同步选择：在任一位置选中对象，其他位置立即定位到同一对象。

UI/UX 第一轮只重点验证五条真实工作路径：

```text
打开项目
点击元素
修改文字
创建动画
编辑视频
```

第一版界面目标是“像一个真正的专业工具”，而不是优先追求品牌动画、装饰效果或大量低频面板。

## 4. 交互体验基线

1. **直接操作**：主要编辑动作能够在画布或时间线直接完成。
2. **即时反馈**：拖动、缩放、裁切、时间定位和参数修改立即反映到画布。
3. **非破坏性编辑**：关键操作支持撤销、重做、版本记录和恢复。
4. **一致选择关系**：场景、DOM、时间线和属性面板始终指向同一对象。
5. **专业快捷操作**：支持多选、复制、粘贴、对齐、吸附、锁定和键盘快捷键。
6. **错误可见**：加载、脚本、媒体和保存错误不得静默发生。
7. **源码可审查**：用户能够查看 HTML Edit 产生的变更，而不是面对不可理解的整文件重写。
8. **人工优先**：所有 MVP 流程必须无需 Agent 即可完整完成。

## 5. 统一项目模型

一个项目由两类数据共同构成。

### 5.1 用户项目源码

```text
HTML / CSS / JavaScript / Assets
```

这些文件是真正网页，也是项目的 Source of Truth。标准 HTML 项目必须能够脱离 HTML Edit 独立运行和继续开发。

### 5.2 HTML Edit 附加数据

```text
user-project/
├─ index.html
├─ styles/
├─ scripts/
├─ assets/
├─ html-edit.generated.css
└─ .html-edit/
   ├─ project.json
   ├─ timeline.json
   ├─ interactions.json
   └─ history/
```

其中：

- `project.json`：项目入口、版本、页面、素材和编辑器设置；
- `timeline.json`：场景、轨道、片段、关键帧和时间参数；
- `interactions.json`：触发器、动作和状态关系；
- `history/`：必要的恢复信息与结构化变更记录；
- `html-edit.generated.css`：可视化编辑产生的非破坏样式。

HTML Edit 不得把某个第三方网页编辑器的私有 Project JSON 设为项目主真相。

## 6. 第一阶段最低成立条件

第一阶段只有同时满足以下条件，才算形成有效闭环：

- 能够导入并运行普通标准 HTML 项目；
- 能够在真实画布中悬停、选择和定位基础 DOM；
- 图层树、画布和属性面板能够同步选择；
- 能够修改文字、图片、视频和基础样式；
- 能够拖动、缩放和多选受支持元素；
- 所有修改进入统一 Command / Operation 与 Undo / Redo；
- 修改能够最小化、安全地回写源码；
- 保存、关闭并重新打开后，结果保持正确；
- 原项目无关源码不会产生大面积无意义变化；
- 项目仍能作为标准 HTML、CSS、JavaScript 独立运行。

**Agent、MCP、云端协作和最终 MP4 导出不属于第一阶段验收条件。**

## 7. 第一版三阶段顺序

### 阶段一：真实 HTML 编辑闭环

```text
打开 → 选择 → 修改 → 撤销 → 保存 → 重开
```

重点解决 Preview Bridge、稳定 ID、Source Patch、生成 CSS 和项目安全保存。

### 阶段二：多轨时间线与媒体同步

```text
Track / Clip / Playhead / Scrub / Keyframe
+ DOM / Video / Audio
```

重点解决统一时间基准、关键帧、片段编辑和可靠回看。

### 阶段三：交互、稳定性与桌面产品化

```text
Trigger / Action
+ 快捷键
+ 错误恢复
+ 自动测试
+ Windows 安装包
```

完成后再评估 Agent、插件、云端和高级媒体能力。

## 8. 当前范围边界

第一版不包括：

- WordPress、电商或通用 CMS 建站能力；
- 完整替代 Premiere、剪映或 After Effects 的视频后期能力；
- 专业调色、完整音频混音台和高级合成；
- 以静态设计画布替代真实 HTML；
- React、Vue、Next.js 等框架项目的完整源码级双向编辑；
- 云端账号、数据库、云存储和多人 CRDT；
- 模板市场、素材商城等平台运营功能；
- Agent、MCP 或插件生态的正式产品化；
- 只能由 Agent 生成、无法人工完整编辑的工作方式；
- 将最终 MP4 导出作为最前面的 P0 条件。

视频成片渲染可以后续扩展，但当前核心交付物首先是：

> **可运行、可交互、可安全保存、可继续编辑的标准 HTML 项目。**

## 9. 技术路线边界

第一版采用“自研核心 + 成熟基础库”，不选择以下路线作为产品地基：

- GrapesJS 二次开发；
- Pinegrow 插件化或产品内嵌；
- Pencil / `.pen` 画布内核；
- Webstudio Fork；
- 从浏览器、解析器、拖拽控件到动画插值全部自行重造。

这些产品或项目可以作为参考，但不得改变以下根本决策：

```text
HTML/CSS/JS 是真实项目
HTML Edit 拥有自己的 Command、Source Patch、Timeline、Interaction 和 Export Model
```

## 10. 后续判断标准

任何新增功能或技术方案必须先回答：

1. 是否直接改善人工编辑真实 HTML 的体验？
2. 是否能够安全回写并保留原项目结构？
3. 是否能进入统一的时间线或交互模型？
4. 是否使用稳定 ID 与统一 Command / Operation？
5. 是否可追踪、可撤销、可恢复？
6. 是否避免把产品锁进第三方私有项目模型？
7. 是否属于当前阶段，而不是过早扩张 Agent、云端或平台能力？

不满足上述标准的内容，不进入当前产品基线。
