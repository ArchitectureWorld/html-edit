# HTML Edit 产品核心定义

> 状态：已确认的产品基线。本文档是当前产品核心与范围边界的唯一权威来源；暂不包含技术选型、系统架构和开发排期。

## 1. 产品定义

**HTML Edit 是一个 Agent 原生的可视化多媒体 HTML 编排器。**

它以真实运行的 HTML、CSS 和 JavaScript 页面作为编辑画布，以成熟非线性剪辑软件的多轨时间线编排页面元素、媒体、动画和交互，并允许人工、自制 Agent 与通用 Agent 共同读写同一个项目。

核心关系为：

```text
真实 HTML 可视化画布
+ 多轨时间线
+ 页面交互与状态编排
+ Agent 原生协同
```

HTML Edit 不是把网页截图放入视频时间线，也不是用私有画布替代 HTML。编辑对象、浏览器预览对象和最终运行对象必须保持一致。

## 2. 四项核心能力

### 2.1 真实 HTML 可视化编辑

编辑器必须直接处理标准 HTML 项目，并在真实浏览器运行环境中完成可视化编辑。

必须支持：

- 打开、保存和继续维护标准 HTML、CSS、JavaScript 项目；
- 在画布中选择真实 DOM 元素；
- 直接编辑文字、图片、视频、SVG、容器和自定义组件；
- 调整布局、尺寸、间距、层级、样式和响应式状态；
- 让画布、DOM 图层树、属性面板和源码保持双向同步；
- 保留项目原有结构与运行能力，不将页面扁平化为截图或不可回编的私有格式。

核心原则：

```text
画布中的对象 = 浏览器中运行的对象 = Agent 读取和修改的对象
```

### 2.2 剪辑软件式多轨时间线

时间线是产品主编辑界面之一，不是附加的动画插件。

时间线需要统一管理：

- 场景与章节；
- DOM 元素及其 CSS 属性；
- 视频、音频和字幕；
- SVG、Canvas、WebGL 与自定义组件状态；
- 进入、停留、退出和场景转场；
- 与时间有关的交互事件。

基础编辑体验必须达到成熟剪辑软件的通用标准：

- 播放、暂停、逐帧或按时间基准定位；
- 时间游标拖动与实时画面回看；
- 多轨道排列、分组和嵌套；
- 片段拖动、裁切、拆分和复制；
- 时间吸附、轨道锁定、显示、隐藏和静音；
- 关键帧的增加、删除、移动和复制；
- 缓动曲线与动画区间调整；
- 时间轴缩放和快捷键操作。

时间线中的数据必须能够被结构化读取和修改，而不是只存在于不可解析的脚本中。

### 2.3 页面交互与状态编排

产品编辑的对象是可交互页面，而不仅是按固定时间播放的动画。

交互触发至少包括：

- 点击；
- 悬停；
- 滚动；
- 键盘输入；
- 页面进入与离开；
- 媒体播放进度；
- 组件状态变化；
- 时间线事件。

交互结果至少包括：

- 播放或切换动画；
- 修改样式和属性；
- 显示、隐藏或替换内容；
- 切换组件状态；
- 页面、场景或锚点跳转；
- 控制视频和音频；
- 调用自定义组件动作。

固定时间动画和用户触发交互必须能够在同一页面中共存，并具有明确的优先级、状态和回退逻辑。

### 2.4 Agent 原生协同

Agent 必须通过结构化接口直接操作项目，而不是仅依赖模拟鼠标和键盘。

Agent 应能够读取：

- 项目与场景结构；
- DOM 图层树和当前选中对象；
- 组件属性、样式和状态；
- 素材及其引用关系；
- 时间线、轨道、片段和关键帧；
- 交互触发器与动作；
- 页面截图、运行错误和预览结果。

Agent 应能够执行：

- 创建、修改、移动和删除页面元素；
- 修改内容、布局和样式；
- 创建和调整场景、轨道、片段和关键帧；
- 设置交互触发器和动作；
- 替换或添加素材；
- 运行预览、截图检查和错误修复。

对接对象包括：

- 自制专业 Agent；
- 通用编码 Agent；
- 通过 MCP 接入的外部 Agent；
- 通过 API 或插件 SDK 接入的服务。

Agent 的每次修改都必须是可追踪、可预览、可比较和可撤销的结构化变更。人工始终能够查看修改差异并决定接受、调整或回退。

## 3. 核心界面结构

产品采用设计工具与剪辑软件共同形成的基本布局：

```text
┌──────────────────────────────────────────────────────────────┐
│ 项目、撤销重做、模式切换、预览与保存                         │
├──────────────┬────────────────────────────┬──────────────────┤
│ 场景 / DOM树 │                            │ 属性 / 样式      │
│ 组件 / 素材  │       真实 HTML 画布        │ 动画 / 交互      │
│              │                            │ 组件参数         │
├──────────────┴────────────────────────────┴──────────────────┤
│ 多轨时间线：场景 / DOM / 视频 / 音频 / 字幕 / 事件 / 状态    │
└──────────────────────────────────────────────────────────────┘
```

画布、图层树、属性面板和时间线之间必须同步选择：在任一位置选中对象，其他位置立即定位到同一对象。

## 4. 交互体验基线

产品交互应遵循以下要求：

1. **直接操作**：主要编辑动作能够通过画布或时间线直接完成，而不是依赖复杂表单。
2. **即时反馈**：拖动、缩放、裁切、时间定位和参数修改能够实时反映到画布。
3. **非破坏性编辑**：关键操作支持撤销、重做、版本记录和恢复。
4. **一致选择关系**：场景、DOM、时间线和属性面板始终指向同一对象。
5. **专业快捷操作**：支持多选、复制、粘贴、对齐、吸附、锁定和键盘快捷键。
6. **人工与 Agent 对等**：Agent 产生的修改在界面中完整可见，人工修改也能被 Agent 结构化读取。

## 5. 统一项目模型

一个完整项目由以下数据共同构成：

1. 标准 HTML、CSS 和 JavaScript 运行源码；
2. 项目、页面、场景和组件的结构化信息；
3. 时间线、轨道、片段和关键帧数据；
4. 交互触发器、动作和状态数据；
5. 图片、视频、音频、字体和其他素材引用；
6. 编辑历史与 Agent 变更记录。

每个可编辑对象必须拥有稳定且唯一的 ID。DOM、时间线、交互系统、属性面板和 Agent 都通过同一 ID 指向该对象，避免依赖容易变化的 CSS 选择器或图层顺序。

标准 HTML 项目始终可以脱离 HTML Edit 独立运行；编辑器附加数据用于保存时间线、交互和协同信息，不应形成不可导出的平台锁定。

## 6. 第一阶段最低成立条件

第一阶段产品只有同时满足以下条件，才算形成有效闭环：

- 能够导入并保存现有标准 HTML 项目；
- 能够在真实画布中编辑基础 DOM 内容、布局和样式；
- 能够通过多轨时间线控制 DOM、视频、音频和关键帧动画；
- 能够设置基础页面交互和组件状态；
- 能够让自制或通用 Agent 结构化读取并修改项目；
- Agent 修改具有差异预览、确认和撤销能力；
- 项目能够以标准 HTML、CSS、JavaScript 形式继续运行和开发。

## 7. 当前范围边界

当前产品核心不包括：

- WordPress、电商或通用 CMS 建站能力；
- 完整替代 Premiere、剪映或 After Effects 的视频后期能力；
- 用静态设计画布替代真实 HTML；
- 模板市场、素材商城等平台运营功能；
- 只能由 Agent 生成、无法人工完整编辑的工作方式。

视频成片渲染可以作为后续扩展，但当前核心交付物首先是**可运行、可交互、可继续编辑的标准 HTML 项目**。

## 8. 后续讨论的判断标准

任何新增功能或技术方案都应先回答：

1. 是否直接服务于真实 HTML 的可视化编辑？
2. 是否能够进入统一的时间线或交互模型？
3. 是否能够被人工与 Agent 共同读取和修改？
4. 是否可追踪、可撤销且不破坏原项目？
5. 是否改善专业编辑体验，而不是引入无关的平台功能？

不满足上述标准的内容，不进入当前产品核心。
